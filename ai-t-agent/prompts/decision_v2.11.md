# Decision Prompt v2.11

日期：2026-08-24 晚（盘后审查，待 8/25 生效）

## 审查结论

对照 8/24 实盘 Prompt：**数据并不缺**（价格、可卖、预计算偏离、预算都在）。
真正的问题是硬约束互相拆台，以及「当前可执行的计划步骤」没有写成账户事实。

| 现象 | 当时 Prompt 实际长什么样 | 归类 |
|:---|:---|:---|
| 09:31–09:34 同分钟 SELL+BUY | 硬约束只有「最多可买100股」；计划一行里同时写卖点和买点；规则8在第8条 | 约束优先级 + 计划未拆成当前步骤 |
| 13:54/13:57 同分钟两腿 + T+1 | 硬约束同时写「禁止SELL」「最多可买100股」「只可HOLD」 | 约束互斥失败 |
| 「接近MA5/MA20」 | 预计算已有较MA5-2.0%、较MA20+2.0%，模型仍说两边都「附近」 | 数据缺元差，弱模型把百分比当附近 |

不改：不因仓位高于目标而禁卖（那是择时，不是事实）。

## v2.11 变更（engine.py）

### 1. 硬约束互斥
预算已闭环（做T次数用尽且无未接回）→ 只保留「只可HOLD」，不再并列「最多可买N股」。
未接回 → 只保留接回BUY句，不再给通用买入通行证。
行情行买卖提示与硬约束同一套事实。

### 2. 当前可执行步骤（先卖后买且可卖>0）
```
{code} 当前可执行步骤：卖出（可卖N股）；买入须等卖出成交后的后续分钟
```
计划行追加 `当前可执行=...`（HOLD / 接回买入 / 卖出 / 买入建仓）。

### 3. 全局执行事实（硬约束置顶）
同一标的同一分钟只能一个方向；同时输出 BUY 和 SELL 两条都会被丢弃。
（执行层已如此，补进硬约束是把事实提前告诉模型。）

### 4. 预计算补元差
`较MA5-2.1%（-0.37元）`，仍是数值，不加「附近/远离」标签。
日内均价同样补元差。

### 5. 二次审查补丁（同晚，未单独升版）
可卖>0、当前步骤为卖出时：硬约束不再并列「最多可买N股」（那是 09:31 的买入通行证）。
容量改写进行情行：`本分钟当前步骤为卖出，禁止与SELL同时发出BUY；卖出成交后买入容量上限N股`。
未接回状态不再误标「当前可执行=卖出」。
T+1 / 只可HOLD 同步写进行情行禁卖，避免只在持仓/硬约束出现。
