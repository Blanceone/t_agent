# AI-T-Agent

**Personal AI Quant Trading Agent — 个人 AI 量化日内做 T 交易系统（模拟盘）**

基于 **Rule + LLM** 架构的 A 股日内做 T 智能体：围绕股票池标的进行分钟级
"高抛低吸" 决策，目标是在控制回撤的前提下，长期持续跑赢等权基准与 Buy & Hold。

## 2. 设计哲学与核心原则

来自 PRD Chapter 0，为项目最高设计标准，任何改动不得违反：

### Rule + LLM：代码为体，模型为脑，Memory 为魂

| 有唯一答案 → 代码（Rule） | 需要判断 → LLM |
|:---|:---|
| T+1、涨跌停、费用计算、现金预留 | 市场理解（Regime）、做 T 时机 |
| 撮合、风控状态机、强制清仓 | 今日计划、多信号仲裁、复盘归因 |

**LLM 只能提建议**：所有 LLM 输出的交易指令必须经 Risk Engine 校验后才能执行，
LLM 永远不直接接触账户修改、风控执行、撮合。

### Prompt 数据原则（实盘迭代中确立，必须遵守）

1. **预计算优先**：凡能代码算出的数值（相对均线/支撑/压力的偏离 ±%、
   区间分位、多窗口涨跌幅），在数据生成层算好直接给模型，
   **禁止让模型心算**（弱模型会算错：曾把 18.23 误判为低于 MA20=17.38）
2. **只给数据，不干预判断，除非必要的兜底**：
   - 预计算只输出客观数值，不输出结论性标签（如"急跌/横盘"）
   - 规则区不添加"XX 情况禁止买入"类替代模型判断的条款
   - 唯一例外是账户/流动性事实性硬约束（无持仓禁卖、T+1、现金上限等）
3. **软约束优先**：优先通过数据与提示词引导行为，不轻易加硬编码限制；
   熔断类硬限制须有实盘数据支撑才实施

### 迭代方法论

- **数据驱动**：每次 Prompt/逻辑改动必须源于真实日志中的具体问题，改后次日验证
- **系统性审查优先于点对点修复**：发现一个问题先检查同类问题是否存在
- **版本化管理**：决策 Prompt 每次变更升版本号（当前 decision.v2.30，线上仍为 v2.29），存档至 `prompts/`；
  Planner / MU 有独立版本号，改了必须同步 bump
- **关键决策证据必须可追溯**：Planner 输出、每 Tick 完整 Prompt 与 LLM 原始
  响应必须落盘（8/20 根因调查曾因缺失这些证据受阻，v2.8 同期补全）

## 3. 系统架构

### 单向调用流

```
Scheduler → Market → Feature → Planner → Decision → Risk → Trading → Replay → Reflection → Memory
```

### 每日生命周期（Scheduler 驱动）

```
09:20 日切（_on_day_start）
  ├── reload CLI 信号文件（账户/股票池变更生效）
  ├── T+1 解冻（昨日买入今日可卖）/ 冷却清理
  ├── 基准组合检查（watchlist 变更时重建 equal_weight）
  ├── 昨日复盘摘要加载（详版给 MU/Planner，简版给决策层）
  ├── 行情刷新后 reset_intraday（开盘至今从 09:30 起算，不含竞价快照）
  ├── Market Understanding：四态 Regime 判定（代码规则优先 + LLM 确认）
  └── Planner：生成今日计划（相对价条件，禁止把 09:20 价冻成全日成交带）

09:30-11:30 / 13:00-14:57 每分钟 Tick（tick.py）
  ├── 行情刷新（腾讯接口）+ 日内轨迹记录
  ├── RiskGuard：止损/日亏/回撤检查 → 风控状态机
  ├── LiquidationWorker：清仓队列执行
  ├── Decision（LLM，1次/分钟）：构建 Prompt → LLM → 解析 → 校验
  ├── Risk 校验：逐单检查（无持仓禁卖/T+1/现金/仓位上限/T预算）
  └── Trading 执行：撮合 → 记账 → 费用 → 持久化

14:57 挂起（停止决策，防止尾盘集合竞价误操作）

15:05 日终（_on_day_close）
  ├── Reflection：代码统计（盈亏归因/买卖结构/费用）+ LLM 归因（50字）
  ├── Memory 写入（复盘摘要入库，可被后续交易日召回）
  ├── 日报生成（data/reports/YYYY-MM-DD_daily.json）
  └── Replay 快照
```

## 5. 核心运行机制

### 5.1 做 T 语义（v2.6 起，务必理解）

- **一次做 T = 先高位卖出 + 后低位买回**，T 预算按"做 T 次数"计
- 卖出后未接回时，**买回属于同一次做 T，不占用新预算**
  （实现：`sells_by_code - buys_by_code` 股数差 > 0 即 pending_buyback）
- **接回不强制当日**：当日无合适低位价格可等后续交易日，不得为接回而接回
- **接回不是加仓**（v2.14）：仓位高于目标时仍允许接回未接回股数；禁止加仓 ≠ 禁止接回
- T 预算耗尽且无未接回股数 → 停止交易只可 HOLD

### 5.2 风控分层

| 级别 | 触发 | 行为 |
|:---|:---|:---|
| NORMAL | 默认 | 正常交易 |
| HALT | 日亏≥3% 或 已实现亏损≥500 元 | 禁止买入，仅允许卖出 |
| LIQUIDATE | 回撤≥10%（相对 peak_nav） | 强制清仓 |

其他：个股止损（成本×0.92，连续 2 分钟击穿确认）、置信度过滤（<0.60 转 HOLD）、
现金预留（净值×20%）。单票市值上限为净值×100%（由现金预留先卡住，仓位手数交给模型）。

**风控拒绝会记录日志** `decision_risk_rejected`（warning 级），撮合拒绝记录
`order_rejected_by_matcher`——排查异常交易行为从这两个事件入手。

### 5.3 基准组合（equal_weight）

- 股票池每票等额虚拟持有，与账户净值对比计算超额收益
- 仅当 **watchlist 真实变更**时重建；注意历史 bug：重启后
  `_last_watchlist` 未初始化会误判变更导致基准净值跳变（已修复：
  `Scheduler.__init__` 用账户清单初始化）

### 5.4 CLI 与常驻服务的双进程一致性

CLI 与服务是**独立进程**，各自持有账户内存副本。CLI 修改（ADD/REMOVE/SET_CASH/
CLEAR_ALL）后写信号文件 `data/account/cli_changed.flag`，服务在每个 Tick 开头和
日切时检查并 reload 账户，避免服务的 `persist()` 用旧副本覆盖 CLI 修改。
**修改账户相关代码时务必保持此机制。**

### 5.5 复盘摘要差异化注入（2026-08-19 起）

`scheduler._load_yesterday_summary(today, brief)`：

- **详版**（MU/Planner，每日 1 次）：日盈亏/交易笔数/Regime/超额 +
  盈亏拆分（做T盈亏、持仓浮动）+ 买卖结构（买X/卖Y、费用）
- **简版**（决策层，每分钟注入）：仅核心 4 字段，避免注意力稀释

### 5.6 可观测性（2026-08-20 补全，根因调查必需）

| 证据 | 位置 | 内容 |
|:---|:---|:---|
| Planner 计划全文 | `agent.log` 事件 `planner_output` | 策略/预算上限/目标仓位/风险/trade_plan 全文/degraded |
| 每 Tick 决策全量快照 | `data/replay/{日期}/prompts.jsonl` | 完整 Prompt + LLM 原始响应 + 解析决策 + 矛盾过滤记录 + 执行/拒单明细 |

此前 `ReplayStore` 从未被主链路调用（replay 目录长期为空），计划内容也不落日志；
现在每 Tick 落盘约 2KB，全日约 500KB。

### 5.7 行情数据源

**腾讯接口**（`qt.gtimg.cn`）。实测经验：东财限流、新浪封服务器 IP，腾讯稳定。
K 线技术位（MA5/MA20、近5日低点/高点）由**已收盘**日 K 在 09:20 冻结，
**禁止用当日未完成 K 热更新 MA**。个股量比 = 今日成交量 / 近 5 日已收盘均量（盘中随成交更新）。

买卖一档（v2.18 起按真实档位解析，不再用现价冒充）：买一=`f[9]`、买一量=`f[10]`、
卖一=`f[19]`、卖一量=`f[20]`。撮合与 Prompt 口径一致：**买入按卖一、卖出按买一**。

09:20 先刷新行情再 `reset_intraday()`，使「开盘至今」从 09:30 连续竞价起算，
不把集合竞价快照（如 16.67）当成开盘后轨迹。

### 5.8 撮合（模拟盘）

`trading/matcher.py`：买入必须 100 股整数倍（非整百不静默取整，返回 `INVALID_LOT`）；
卖出须整手，或等于全部可卖（清仓允许零股）。零滑点，收益不可线性外推实盘。

## 6. 决策 Prompt 数据清单与版本演进

### 6.1 当前 Prompt 结构（decision.v2.30）

决策引擎每分钟构建一次 Prompt，区块顺序：

| 区块 | 内容 | 性质 |
|:---|:---|:---|
| 文首 | 买入按卖一、卖出按买一；计划是开盘框架；今日已成交只记当天买卖；未接回是账户事实不是买入上限；上限0不是次数已满；本次股数可小于可卖、买入可超过未接回；仓位/区间位置/接回价差是数据不是硬指令；推理前先读今日已成交与先前结论 | 契约 |
| 硬性约束（置顶） | 同分钟单方向 / 无持仓禁卖 / T+1禁卖 / 次数用尽禁卖仍可买 / 买入容量 | 账户/流动性事实 |
| 市场环境 | Regime + MU 摘要（指数涨跌/振幅/量比，不含「建议减少做T」）、上证指数、昨日复盘摘要（简版） | 数据 |
| 当前状态 | 时钟（连续竞价已过分钟 + 距 14:57）、风控、净值、现金、**购买力**、当日已实现盈亏、费用、回撤 | 数据 |
| 持仓 | 股数/可卖/成本/现价；清仓未接回写持仓0股可卖0股+卖出均价；今日已卖/已买；真空仓才整段写「无持仓」 | 数据 |
| 今日已成交 | 每笔时间/方向/股数/价格/费用（推理前先看，防重复操作） | 跨分钟记忆 |
| 今日先前结论 | 当日最近 30 条模型一句话结论；推理前先读、认真对照；事实未变不要无故推翻，事实已变可改；不是硬指令 | 跨分钟记忆（非硬指令） |
| 风控反馈 | 最近 6 条被拒指令及原因（防重复提交） | 跨分钟记忆 |
| 股票池行情 | 现价/买一卖一及挂单量/涨跌/OHLC/昨收/量额/VWAP/涨跌停空间/技术位/ST停牌/买卖提示 | 数据 |
| └ 预计算 | 较MA5/MA20/支撑/压力/均价/今开±%（含元差）、今开较昨收、振幅、较日内高低、区间分位、开盘至今/近10分/近30分、近1分钟成交、量比、有未接回时接回价差（卖出价−现价，买在上方/下方）、100股往返费用 | 数据（免心算） |
| 日内走势 | 近30分钟最高/最低/涨跌；近10分钟高低先后；全日最高/最低出现时刻与距今分钟 | 数据 |
| 今日计划 | 生成时刻 + 当时现价 vs 当前现价；策略/目标仓位/风险/T预算剩余/trade_plan（相对价条件）/当前可执行 | 上游模型输出 |
| 相关记忆 | 长期记忆库检索 top-k | 历史经验 |
| 规则 | 12 条：可买卖或持有、未接回不是买入上限、整手、同分钟单方向、预计算非禁令；仓位相对目标是数据 | 流程规范 |

模型**不输出成交价**；成交价由撮合用买一/卖一填写。

### 6.2 版本演进（详见 prompts/ 各存档）

| 版本 | 关键变更 | 解决的问题 |
|:---|:---|:---|
| v2.0~v2.2 | 基础做 T 框架 | — |
| v2.3 | 支持建仓（底仓建立）+ 双层约束 | 空池冷启动 |
| v2.4 | 决策规则完善 | — |
| v2.5 | **硬约束置顶** + 条件式表述规范 | 拒单 457/日 → 0 |
| v2.6 | 做 T 预算按次数计；接回不占预算、不强制当日 | 卖飞问题 |
| v2.7 | **预计算数据行**（偏离±%/分位/多窗口），无判断词 | 模型心算错误（高点买入） |

## 7. 配置说明

`config/default.yaml` 为唯一业务配置源（**禁止代码硬编码**），关键项：

```yaml
fee:          # 印花税0.05%（卖）/ 过户费0.001% / 佣金万2.5双边，最低5元
risk:         # 止损0.92 / 日亏熔断3% / 已实现亏损熔断500 / 回撤清仓10%
              # 现金预留20% / 单票上限100% / 置信度阈值0.60
trading:      # initial_cash / watchlist_limit=20
scheduler:    # tick 60s / 日切09:20 / 交易时段 / 挂起14:57 / 日终15:05
llm:          # deepseek / deepseek-v4-flash；密钥 LLM_API_KEY、地址 LLM_BASE_URL
              # extra_body.thinking.type=disabled（V4 默认开思考，盘中 30s 必关）
prompt:       # decision_version / planner_version / market_understanding_version
              # 升级 Prompt 必改此处（当前 decision.v2.30 / planner.v1.9 / MU v1.1）
memory:       # SQLite 路径 / top_k=8 / 30天后压缩
market:       # data_source: tencent
feature:      # volume_ratio_lookback_days=5 / round_trip_est_shares=100
decision:     # hold_on_failure: true（LLM 失败时保持 HOLD 不瞎动）
```

环境变量（`.env`）：`LLM_API_KEY`、`LLM_BASE_URL`、`TUSHARE_TOKEN`。

```
data/

├── logs/agent.log            # structlog JSONL 主日志（STATUS 最近成交读此文件的 order_filled）

├── reports/YYYY-MM-DD_daily.json   # 日报（19字段，复盘摘要数据源）
├── memory/memory.db          # 长期记忆 SQLite
└── replay/{日期}/prompts.jsonl     # 每 Tick 全量快照：Prompt+原始响应+执行明细（8/20 起）
```

**排查决策行为的标准路径**：`replay/{日期}/prompts.jsonl` 看模型当时看到了什么、
回了什么（首选）→ `decisions.jsonl` 找 thought → 对照 `agent.log` 同时刻
行情/拒绝事件 → 对照 state.json 账户事实。

## 13. 开发约定（给接手者）

1. **不要违反设计哲学**：LLM 不碰账户/风控/撮合；有唯一答案的用代码
2. **Prompt 改动三原则**：预计算优先、只给数据不干预判断、软约束优先
3. **一切以实盘日志为准**：先分析 `decisions.jsonl` + `agent.log`，再动手
4. **版本化**：Prompt 升级必须改 `default.yaml` + schema 默认值 + `prompts/` 存档 + 单测（及冒烟）
5. **盘后部署**：交易日 15:05 之后重启服务；先备份再重启；不要上传 `.env`
6. **保持双进程机制**：任何账户写入路径都要考虑 CLI 信号文件兼容性
7. **模型假设**：DeepSeek V4 Flash 强于 GLM-4-Flash，但仍把比较/费用/偏离在数据层算好；
   思考模式保持关闭。硬约束只写账户/流动性事实，不把策略写成禁令
8. **测试底线**：113 个测试必须全绿才能部署
9. **日 K 冻结**：MA/近5日高低只来自已收盘 K，禁止用当日未完成 bar 热更新
